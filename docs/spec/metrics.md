## 10.1 제품 지표 (사용자가 실제로 가치를 느끼나)

목표는 가설이에요. P1 운영 2주 뒤 실제 값을 보고 고쳐요.

| 지표                 | 계산 방법                                     | 목표(가설)          | 보는 이유                 |
|----------------------|-----------------------------------------------|---------------------|---------------------------|
| 활성 스터디 수       | 최근 7일 안에 판정이 있는 그룹 스터디 수      | P4 시작 + 8주에 3개 | 실제 사용                 |
| 주간 활성 사용자     | 최근 7일 안에 풀이 기록이 있는 사용자 수      | 15명                | 실제 사용                 |
| **자동 인증 비율**   | GitHub·복구 풀이 ÷ 전체 풀이                  | 80% 이상            | 자동화 효과               |
| **알림 전환율**      | 알림을 받고 그날 성공한 멤버 ÷ 알림 받은 멤버 | 30% 이상            | 메인 기능의 효과          |
| 일일 성공률          | 성공 ÷ (성공 + 실패)                          | 추세 확인           | 스터디 건강도             |
| 기수 완주율          | 기수 끝까지 남은 멤버 ÷ 기수 시작 멤버        | 70% 이상            | 유지                      |
| 다음 기수 이어가기율 | 이어간 멤버 ÷ 기수 완주 멤버                  | 60% 이상            | 재참여                    |
| 방장 공유율          | 공유한 날 ÷ 공유 카드를 받은 날               | 50% 이상            | 카톡 경로가 실제로 쓰이나 |
| 수동 인증 비율       | 수동 풀이 ÷ 전체 풀이                         | 20% 이하            | 신뢰와 연결 문제 신호     |
| 판정 정정률          | 정정된 판정 ÷ 전체 판정                       | 2% 이하             | 판정 정확도               |
| 전환 깔때기          | 2.5의 단계별 비율                             | 2.5 표              | 어디서 빠지나             |

**알림 전환율 쿼리 예시**

```sql
-- 알림을 받은 멤버 중 그날 목표를 채운 비율
SELECT n.study_day,
       COUNT(*)                                      AS reminded,
       COUNT(*) FILTER (WHERE md.result = 'SUCCESS') AS converted
FROM notifications n
         JOIN member_days md
              ON md.study_id = n.study_id
                  AND md.user_id = n.user_id
                  AND md.study_day = n.study_day
WHERE n.type = 'REMINDER'
  AND n.status = 'SENT'
GROUP BY n.study_day
ORDER BY n.study_day;
```

## 10.2 기술 지표 (서비스가 믿을 만한가)

| 지표                                | 계산 방법                               | 관련  |
