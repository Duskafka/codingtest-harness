## 9.7 보안: 애플리케이션

**로그인과 세션** (4.5)

- 세션은 DB 저장 (D22), 쿠키는 HttpOnly·Secure·SameSite=Lax
- CSRF는 SPA용 공식 설정 그대로, 로그아웃은 POST
- 세션 쿠키는 `__Host-Http-` 접두사 사용 (로컬 개발·브라우저 지원이 안 되면 `__Host-`, 결정 제안서 002)

**권한 (가장 중요)**

- 멤버·방장 검사를 한 곳 (`StudyAccess`)에 모아 모든 API에 적용
- 조회 쿼리도 스터디 ID로 범위를 제한
- 모든 엔드포인트에 다른 스터디 접근 테스트 (T19)

**받는 요청 (웹훅)**

- GitHub: `X-Hub-Signature-256`(HMAC-SHA256)을 원본 바이트로, 상수 시간 비교 [S36]
- 디스코드: Ed25519, 타임스탬프가 오래된 요청 거절 [S32]
- 카카오톡 공유 웹훅 (선택): 카카오가 보낸 요청인지 문서의 방식대로 확인 [S29]
- 요청 크기 제한, delivery·interaction id로 중복 거절

**보내는 요청 (SSRF 방지)**

서버가 사용자가 입력한 주소로 요청을 보내는 곳이 두 군데 있어요. 그대로 두면 공격자가 내부 주소 (예: 클라우드 메타데이터 주소 `169.254.169.254`)로 요청을 보내게 만들 수 있어요.

- 디스코드 웹훅 URL: `https://discord.com/api/webhooks/` 같은 공식 주소로 시작하는 것만 허용 (T27)
- 웹 푸시 구독 주소: 알려진 푸시 서비스 도메인만 허용 (정확한 목록은 구현 때 확인) (T28)
- 리다이렉트를 따라가지 않기, 응답 시간·크기 제한
- 증거 링크는 표시만 하고 서버가 접속하지 않음

**입력과 출력**

- Bean Validation으로 길이·형식 제한
- 링크는 `http`/`https`만 허용 (`javascript:` 링크 XSS 방지)
- 프론트에서 `dangerouslySetInnerHTML` 쓰지 않기
- 네이티브 쿼리는 파라미터 바인딩만
- 디스코드 게시물은 `allowed_mentions`를 비워서 `@everyone` 장난 차단

**운영 엔드포인트와 오류**

- Actuator는 `health`만 외부 노출. `env`, `heapdump`, `configprops`는 끄기 (노출되면 비밀번호·키가 그대로 유출) [S57]
- 오류 응답에 스택 트레이스·쿼리 노출 금지
- 보안 헤더 (Nginx): CSP (카카오 SDK 도메인만 추가 허용), `frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy`
- `/admin/**`은 Cloudflare Access + 앱 역할 확인

**남용 방지**

- 앱 단 요청 수 제한 (Bucket4j 등): 초대 수락, 수동 인증 (하루 5건), 이의 신청, 테스트 알림

**의존성과 코드**

- Dependabot (Gradle·Docker·Actions)
- 공개 레포라 코드 스캐닝·비밀 스캐닝 무료 사용
