## 7. 프론트엔드 원칙

- **시간 상한:** 개발 시간의 20% (주 약 2.5시간)
- **스택 제안:** React + TypeScript + Vite 정적 빌드 → Nginx가 서빙. PWA (매니페스트 + 서비스 워커)
- **만드는 방법:** springdoc-openapi 명세로 API 클라이언트 타입을 생성하고 (openapi-typescript 등), 화면 단위로 AI 코딩 도구에 맡긴 뒤 직접 검토·수정해요.
- **AI 활용 기록:** 어떤 지시로 어떤 화면을 만들었고 무엇을 고쳤는지 PR의 판단 기록에 남겨요.
- **서비스 워커는 알림 전용으로 단순하게:** 오프라인 캐시 전략을 욕심내면 '배포했는데 옛 화면이 뜨는' 문제가 생겨요. `index.html`은 항상 네트워크에서 받고, 정적 파일은 파일명에 해시를 붙여요.
- **비밀은 프론트에 두지 않아요.** 프론트에 들어가는 값은 VAPID 공개키와 카카오 JavaScript 키 (도메인 제한)뿐이에요.
- **디자인:** 깔끔하게 쓸 수 있는 정도까지만. 오늘 현황과 GitHub 연결 화면에만 공을 들여요 (2.6).
- 화면 목록은 2.6에 있어요.
