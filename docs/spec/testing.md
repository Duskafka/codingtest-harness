# 테스트 전략

> 스펙 문서예요. 에이전트는 고치지 않아요. T번호가 어느 단계에서 구현되는지는 `docs/steps/README.md`의 'T번호 배치'에 있어요.

## 하네스 규칙

에이전트가 테스트를 다룰 때 지키는 규칙이에요.

- **테스트 이름에 T번호를 붙여요.** 예: `@DisplayName("T7: 00:05에 push 2개가 동시에 오면 전날 1, 오늘 1")`. `grep -rn "T7:" src/test`로 찾을 수 있어야 해요.
- **테스트를 먼저 써요.** 단계의 수용 기준을 테스트로 옮기고, 실패하는 걸 확인한 뒤 구현해요.
- **이미 master에 있는 테스트는 약하게 만들지 않아요.** 기대값 바꾸기, 지우기, `@Disabled`로 끄기를 하지 않아요. 꼭 필요하면 PR에 이유를 적고 '꼭 봐 주세요'로 표시해요.
- **시간은 고정 `Clock`으로** 재현해요. 동시성은 여러 스레드 + `CountDownLatch`로, 비동기는 Awaitility로 기다려요. `Thread.sleep`으로 타이밍을 맞추지 않아요.
- **외부 시스템은 WireMock으로** 흉내 내요. 실제 네트워크에 기대는 테스트를 만들지 않아요.
- **DB가 필요한 테스트는 Testcontainers(PostgreSQL 17)로** 해요. H2 같은 내장 DB로 대신하지 않아요. 행 잠금, 부분 UNIQUE, JSONB, `ON CONFLICT` 동작이 달라요.
- **규칙(R)마다 테스트가 최소 1개** 있어야 해요 (8.1 원칙).

## 8.1 층별 테스트

| 종류     | 대상                                                                | 도구                               |
|----------|---------------------------------------------------------------------|------------------------------------|
| 단위     | `StudyCalendar`, 배정(R4), 판정 규칙(R9), 원장 잔액, 문제 식별 파서 | JUnit 5, AssertJ, 고정 `Clock`     |
| 통합     | 저장소, 유니크 제약, 잠금, 판정 배치, 원장, Flyway 마이그레이션     | Testcontainers(PostgreSQL)         |
| 웹훅     | 서명 검증, 중복, 순서, 실제 payload 샘플                            | MockMvc + 저장해 둔 GitHub payload |
| 동시성   | 배정 경합, 면제권 경합, 이의 동시 결정, 정원 경합                   | 여러 스레드 + CountDownLatch       |
| 외부 API | GitHub API, 웹 푸시, 디스코드의 지연·실패·한도 초과                 | WireMock                           |
| 비동기   | inbox 워커, 알림 발송기                                             | Awaitility                         |
| 구조     | 모듈 의존 방향(4.2)                                                 | ArchUnit                           |
| 보안     | 권한(IDOR), CSRF, 서명, URL 검증                                    | MockMvc                            |
| CI       | 모든 PR에서 빌드와 테스트                                           | GitHub Actions                     |

원칙: **규칙 (R)마다 테스트가 최소 1개** 있어야 하고, 5장의 '테스트' 항목이 모두 초록색이어야 해당 프로세스가 끝난 거예요.
