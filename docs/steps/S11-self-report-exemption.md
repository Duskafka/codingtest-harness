## 만들 것

1. **수동 인증 제출:** `POST /api/studies/{id}/self-reports`. 오늘 또는 유예 중인 전날만, 하루 5건까지. 증거 링크는 `http`·`https`만 받고 서버는 접속하지 않는다.
2. **바로 인정 (기본):** 풀이 기록(`SELF_REPORT`)을 만들고 S09 배정으로 바로 집계한다. 인정 시각은 제출 시각이다 (R3).
3. **본인 철회:** `DELETE /api/studies/{id}/self-reports/{rid}`. 판정 전에만. 집계에서 빠진다.
4. **현황의 '수동' 표시**와 멤버별 수동 인증 비율(방장에게).
5. **면제권 사용·취소:** `POST /api/studies/{id}/exemptions`, `DELETE /api/studies/{id}/exemptions/{studyDay}`. 기준 시각 전, 쉬는 날이 아님, 이미 달성하지 않음. 멤버십 행을 잠가 한 사용자의 면제권 계산을 한 줄로 세우고, 기수 한도를 확인한다.
6. **남은 면제권 개수**를 응답과 현황에 담는다.

## 만들지 않을 것

- '승인 필요' 모드. 4.4에 승인·거부 API가 없어서 PR의 '스펙 변경 제안'으로 올리고, 승인되기 전에는 만들지 않는다 (알려진 충돌 6번)
- 수동 인증에 대한 반대 이의 (P2)
- 남용 방지용 요청 수 제한 (P2 백로그)

## 주의할 것

- 마지막 면제권 경쟁은 멤버 일 행 잠금으로는 못 막는다. 날짜마다 행이 다르기 때문이다. 멤버십 행을 잠근다 (5.7).
- 판정 뒤 결과를 바꾸는 일은 이의(P2)로만 한다. 수동 인증으로 지난 판정을 바꾸지 않는다 (5.6).
