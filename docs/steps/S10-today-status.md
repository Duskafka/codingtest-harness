| 항목 | 내용 |

## 목표

멤버가 가장 자주 보는 '오늘 현황'과 '내 풀이'를 만들고, 확인 대기 풀이에 문제를 지정할 수 있게 한다. 조회 성능을 측정할 수 있는 형태로 만든다 (6장 ⑤).

## 읽을 문서

- `docs/spec/api.md`: 4.4의 현황·풀이 행, 4.4 아래 페이지네이션 항목
- `docs/spec/product.md`: 2.6의 6번(오늘 현황)·7번(내 풀이) 화면
- `docs/spec/processes/5.04-problem-identification.md`: 확인 대기
- `docs/spec/domain-rules.md`: R6
- `docs/spec/architecture.md`: 6장 ⑤

## 만들 것

1. `GET /api/studies/{id}/today`: 멤버별 완료·남음·면제, 최근 풀이, 수동 인증 표시 자리
2. `GET /api/studies/{id}/days/{date}`: 특정 날 상세
3. `GET /api/me/solves?from=&to=`: 내 풀이 (확인 대기 포함), 페이지네이션
4. `PATCH /api/me/solves/{id}`: 확인 대기 풀이에 문제를 지정한다. 원래 수신 시각 기준으로 배정한다 (R6). 그날이 이미 판정됐으면 바꾸지 않고, 이의(P2)가 필요하다는 problem+json 409로 안내한다
5. **조회 전용 쿼리:** 엔티티를 그대로 내보내지 않고 조회용 DTO로 가져온다. 스터디·날짜 단위로 한 번에 가져온다

## 만들지 않을 것

- 미인증 횟수 × 금액 표시 (S12에서 현황 응답에 더함)
- 공유 카드 (S14)

## 수용 기준

- [ ] 오늘 현황이 멤버별 완료·남음·면제를 규칙대로 보여 준다 (3.5 예시로 확인)
- [ ] 오늘 현황의 쿼리 수가 멤버 수와 상관없이 일정하다 (멤버 3명과 30명에서 같은 쿼리 수, Hibernate 통계로 확인)
- [ ] T26: 확인 대기 풀이에 문제를 지정하면 원래 수신 시각 기준의 스터디 일에 반영된다
- [ ] 이미 판정된 날의 확인 대기 풀이에 문제를 지정하면 409이고 아무것도 바뀌지 않는다
- [ ] 남의 풀이에 문제를 지정할 수 없다
- [ ] 목록 API는 페이지 크기 상한이 있다
- [ ] T19: 이 단계의 엔드포인트에서 다른 스터디·다른 사용자의 데이터에 접근할 수 없다

## 주의할 것

- Supabase egress를 아끼려면 큰 응답을 만들지 않는다 (9.4).
- 응답 모양은 프론트(S16)가 쓰는 계약이다.
- 확인 대기의 원래 수신 시각이 그 스터디에 가입하기 전이어도 그날에 기록한다 (사람이 정함, 2026-11-25 S09 PR #24). 배정은 지정할 때의 멤버십으로 가린다 (R14): 탈퇴 전에 받았어도 탈퇴 뒤에 지정하면 세지 않고, 가입 전에 받았어도 가입한 뒤에 지정하면 센다. 그날이 이미 판정됐으면 만들 것 4대로 409다.

## 판단 기록이 필요한 곳

- 현황 응답의 모양 ('꼭 봐 주세요')
- 쿼리 작성 방식 (JPQL DTO 프로젝션, 네이티브 쿼리 등)과 측정 결과 (쿼리 수, 응답 시간)
