## 목표

풀이를 규칙 R4·R5대로 정확한 스터디 일에 배정하고, 동시에 와도 한 번만 센다. 이 서비스에서 동시성이 가장 까다로운 곳이다.

## 만들 것

1. **`planStudyDay`·`assignStudyDay`:** 부록 D대로. 전날의 목표·쉬는 날 판단에는 전날의 규칙 버전을 쓴다. 스터디 일과 유예 구간은 `common.time.RuleVersionCalendar`(`studyDayOf`, `isInGrace`)로 센다. 유예는 그 구간이 시작되는 날 N의 규칙을 쓴다 (부록 D `rule(N).grace`, R4).
2. **멤버 일 잠금:** `INSERT ... ON CONFLICT DO NOTHING` 다음 `SELECT ... FOR UPDATE`. 잠금 순서는 풀이 하나마다 잠글 행(후보 전날, 오늘)을 모든 스터디에 걸쳐 모아 (스터디 일, 스터디 ID) 순서로 (5.5, 결정 제안서 007).
3. **판정 대상 여부 (R9):** 가입(`judged_from`), 탈퇴(`left_at`), 기수를 반영한다. 기수 밖인 날(1기 시작 전 등)은 판정 대상이 아니다 (R9, OD-07). 쉬는 요일은 판정 대상과 따로 본다 (R4). 기수 안인지는 `seasons` 행으로 본다. 다음 기수 행은 이번 기수가 시작될 때 S12 판정 배치가 만들어 두니(5.13), S09 테스트는 필요한 기수 행을 직접 넣는다.
4. **집계:** `study_day_solves` INSERT(유니크 제약 R5, 충돌은 무시), `member_days.solved_count`를 그 날의 `study_day_solves` 수로 다시 계산한다.
5. **여러 스터디:** 사용자가 속한 모든 활성 스터디에 반영한다. 한 트랜잭션.
6. **S08 연결:** S08이 만든 배정 연결 지점을 채운다.

## 만들지 않을 것

- 판정 배치 (S12). 단, 판정 배치도 같은 멤버 일 행을 잠근다는 전제로 만든다
- 수동 인증·면제권 사용 API (S11). 면제권이 쓰인 날의 처리는 `exemption_used_at`을 읽어서 반영한다

## 수용 기준

기준 시각 00:00, 유예 30분, 목표 1문제.

- [x] T6: 00:05 수신, 전날 미달 → 전날로 배정 / 전날 이미 달성 → 오늘로 배정
- [x] T7: 00:05에 push 2개가 동시에 도착 → 전날 1, 오늘 1. 여러 번 반복해도 같다 (여러 스레드 + `CountDownLatch`)
- [x] T4: 같은 날 같은 문제를 두 번 커밋 → 1문제로 센다
- [x] T5: force push로 SHA가 바뀐 같은 문제 → 같은 날 1문제
- [x] 유예 밖(00:35) 수신 → 오늘로 배정
- [x] 전날이 이미 판정됐으면 유예 안이어도 오늘로 배정
- [x] 전날이 쉬는 날이거나 면제권을 쓴 날이면 오늘로 배정
- [x] T25: 기준 06:00 스터디의 새벽 03:00 풀이는 전날로 집계되고, 다른 시간대 스터디도 그 시간대 기준으로 배정된다
- [x] 가입 다음 날 00:05의 풀이는 가입한 날(판정 대상 아님, R14)로 배정되지 않고 오늘로 배정된다 (R4의 '판정 대상' 조건)
- [x] 스터디 2개에 속한 사용자의 풀이 하나가 두 스터디에 각각 반영된다

## 주의할 것

- 잠금 순서가 섞이면 교착 상태가 난다 (5.5).
- `LocalDate.now()`를 직접 부르지 않는다. 배정의 기준 시각은 풀이 기록의 인정 시각이다.
- 동시성 테스트는 한 번 통과로 끝내지 않는다. 반복 실행해도 같은지 본다.
