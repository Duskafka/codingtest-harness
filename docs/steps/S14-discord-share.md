## 목표

스터디가 실제로 있는 곳(디스코드, 카톡방)으로 현황과 결과를 보낸다. 디스코드는 자동 게시, 카톡방은 방장이 공유 버튼으로 보낼 카드를 만든다.

## 만들 것

1. **디스코드 웹훅 등록:** `PUT /api/studies/{id}/channels/discord` (등록·해제, 방장). `https://discord.com/api/webhooks/` 같은 공식 주소만 받는다 (T27). URL은 앱 수준에서 암호화해 저장하고, 저장한 뒤에는 다시 보여 주지 않는다.
2. **테스트 게시:** `POST /api/studies/{id}/channels/discord/test`.
3. **`DISCORD_STATUS`:** 알림 시각에 디스코드를 쓰는 스터디의 현황을 임베드 메시지로 게시한다. `allowed_mentions`는 비워서 보낸다.
4. **디스코드 응답 처리:** 429는 응답의 재시도 시간만큼 기다렸다 다시 보낸다. 404면 웹훅이 지워진 것이라 비활성화하고 방장에게 알린다.
5. **`DAILY_RESULT`:** 판정이 끝난 날의 결과를 디스코드 또는 방장 웹 푸시로 보낸다. judgment가 notification을 직접 부르지 않고, 판정이 끝난 날을 DB에서 다시 찾을 수 있는 방식으로 만든다. 방식은 결정 제안서로 쓴다 (알려진 충돌 2번).
6. **공유 카드 API:** `GET /api/studies/{id}/share-card?type=today`. 제목, 요약, 링크. 벌금 금액은 기본으로 넣지 않는다. 카카오톡 공유가 안 되는 환경을 위한 '텍스트 복사'용 텍스트도 담는다.

## 만들지 않을 것

- 카카오 JavaScript SDK와 공유 화면 (S16)
- 주간 정산 카드 (P2), 카카오톡 공유 결과 웹훅 (P3)
- 디스코드 명령 (P3)

## 수용 기준

- [ ] T27: 디스코드 공식 웹훅 주소가 아닌 URL(내부 주소, 다른 도메인)은 거절된다
- [ ] 웹훅 URL이 DB에 평문으로 남지 않고, 조회 응답에도 나오지 않는다
- [ ] T18: 디스코드가 429를 주면 기다렸다 다시 보내고, 404를 주면 비활성화하고 방장 알림을 만든다
- [ ] 게시 메시지의 `allowed_mentions`가 비어 있어 `@everyone`이 동작하지 않는다
- [ ] 판정 배치를 두 번 돌려도 `DAILY_RESULT`는 하루에 하나다
- [ ] 판정 뒤 서버가 죽어 이벤트가 사라져도 `DAILY_RESULT`가 결국 만들어진다
- [ ] 공유 카드에 벌금 금액이 기본으로 들어가지 않는다
- [ ] 디스코드는 WireMock으로 테스트한다
- [ ] T19: 다른 스터디의 공유 카드와 채널 설정에 접근할 수 없다

## 주의할 것

- 웹훅 URL이 새면 누구나 그 채널에 글을 올릴 수 있다. 비밀로 다룬다 (2.7).
- 카드에는 멤버 이름이 들어간다. 스터디 안에서 공유되는 정보지만 금액은 방장이 켤 때만 넣는다 (5.9).

## 판단 기록이 필요한 곳

- **결정 제안서:** `DAILY_RESULT`를 만드는 방식 (알려진 충돌 2번)
- 암호화 방식과 키 교체 절차
- 공유 카드 응답 모양 ('꼭 봐 주세요')
