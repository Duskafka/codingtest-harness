# S02. 시간 계산 (`StudyCalendar`)

| 항목 | 내용 |
|---|---|
| 단계 | P1 |
| 선행 | S01 |

## 목표

스터디 일, 유예, 알림 시각, 판정 시각 계산을 `StudyCalendar` 한 곳에 순수 함수로 모은다. 이후 배정·판정·알림이 모두 이걸 쓴다.

## 읽을 문서

- `docs/spec/domain-rules.md`: 3.1 용어, 3.2의 R1·R4·R9, 3.3 시간 규칙, 3.5 판정 예시
- `docs/spec/processes/5.05-study-day-assignment.md`: '만들 것', '주의할 것'
- `docs/spec/architecture.md`: '알려진 충돌과 빈 곳' 4번
- `docs/spec/glossary.md`: 시간 관련 이름

## 만들 것

1. **시간 규칙 값:** 시간대(`ZoneId`), 하루 기준 시각, 유예(분), 알림 오프셋(분), 쉬는 요일. R1의 범위를 벗어나면 만들 수 없다.
2. **`StudyCalendar` (`common` 모듈):** study 엔티티를 모르고 시간 규칙 값만 받는다.
    - `studyDayOf(Instant)`: 시각이 속한 스터디 일
    - `boundaryOf(LocalDate)`: 그 스터디 일이 시작하는 시각
    - `isInGrace(Instant)`: 시각이 스터디 일 시작부터 유예 안인지
    - `reminderAt(LocalDate)`: `boundaryOf(D+1) − 알림 오프셋` (5.8)
    - `judgeAt(LocalDate)`: `boundaryOf(D+1) + 유예 + 10분` (R9)
    - `isRestDay(LocalDate)`: 쉬는 요일인지
3. 메서드 이름은 5.5의 이름을 따르되, 더 나은 이름이 있으면 판단 기록에 남긴다.

## 만들지 않을 것

- R4의 '전날로 배정' 판단. 멤버 일 상태가 필요해서 S09에서 한다
- 규칙 버전이 바뀌는 날의 경계 처리 (OD-08). 지금은 '그날 적용되는 시간 규칙 하나'로 계산하는 형태로만 만든다

## 수용 기준

기준은 모두 `Asia/Seoul`, 별도 표시가 없으면 기준 시각 00:00, 유예 30분, 알림 120분 전이다.

- [ ] `2026-11-20T23:50+09:00` → 스터디 일 11/20
- [ ] `2026-11-21T00:20+09:00` → 스터디 일 11/21, 유예 안
- [ ] `2026-11-21T00:35+09:00` → 스터디 일 11/21, 유예 밖
- [ ] 기준 시각 06:00 스터디에서 `2026-11-21T03:00+09:00` → 스터디 일 11/20 (T25)
- [ ] `judgeAt(11/20)` = `2026-11-21T00:40+09:00`
- [ ] `reminderAt(11/20)` = `2026-11-20T22:00+09:00`
- [ ] 서머타임이 있는 시간대(예: `America/New_York`)의 전환일 앞뒤에서도 스터디 일이 하루에 한 번씩 바뀐다 (T25)
- [ ] R1 범위 밖 값(유예 121분, 기준 시각 07:00, 알림 오프셋 20분)으로는 시간 규칙을 만들 수 없다
- [ ] 쉬는 요일 판정이 맞다

## 주의할 것

- 날짜 계산은 `ZonedDateTime`으로 한다 (5.10 주의할 것).
- 순수 함수라 `Clock`이 필요 없다. 시각은 인자로 받는다.
- 경계값(정확히 기준 시각, 유예 끝 시각)은 포함/제외를 테스트로 고정한다. 스터디 일은 `[D 기준 시각, D+1 기준 시각)`이다.

## 판단 기록이 필요한 곳

- 서머타임으로 존재하지 않는 시각이나 두 번 있는 시각이 기준 시각일 때의 처리 (`ZonedDateTime`의 기본 해석을 쓸지)
- `StudyCalendar`에 시간 규칙을 넘기는 방식 (알려진 충돌 4번)
